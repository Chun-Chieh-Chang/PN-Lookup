# PN-Lookup 專案 CAPA (Corrective and Preventive Action) 全域規則

## 目的
確保 Agent 在執行複雜任務時保持透明度、及時回報進度、避免無效循環。

---

## 一、Corrective Action (糾正措施)

### 當遇到技術障礙時（如編譯錯誤、文件損壞）：

1. **立即停止**：發現同一問題連續 2 次修復失敗後，必須停止並報告
2. **明確報告**：輸出格式：
   ```
   ⚠️ 障礙報告：[問題名稱]
   - 已嘗試：[方案A]、[方案B]
   - 結果：[失敗原因]
   - 建議：[下一步行動]
   ```
3. **請求決策**：詢問用戶選擇：
   - [ ] A. 恢復到上一個穩定狀態
   - [ ] B. 嘗試替代方案
   - [ ] C. 其他指示

### 當任務進行中斷時：

1. **主動彙總**：輸出當前已完成和待完成項目
2. **提供選項**：明確列出接下來可以做的步驟

---

## 二、Preventive Action (預防措施)

### 1. 里程碑回報機制

**每完成一個主要階段後，必須輸出進度報告：**

```markdown
## 📊 進度回報 [時間戳記]

### 已完成
- [x] 步驟 1: ...
- [x] 步驟 2: ...

### 進行中
- [ ] 步驟 3: ...

### 障礙/風險
- ⚠️ [問題描述]
```

### 2. 工具呼叫頻率限制

- **限制**：每 3-5 次工具呼叫後，必須有一次彙總報告
- **例外**：簡單查詢或快速驗證可連續執行

### 3. 狀態檢查點

在執行以下操作前，先確認當前狀態：
- [ ] 執行破壞性操作（git reset, rm, overwrite）
- [ ] 修改核心配置檔案
- [ ] 切換分支或還原變更

### 4. 任務分解與追蹤

使用 Todo List 追蹤複雜任務：
```markdown
## 任務名稱
- [ ] Step 1: ...
- [ ] Step 2: ...
- [ ] Step 3: ...
```

每完成一個 Step，更新清單並回報進度。

---

## 三、違反處理

若發現自己違反上述規則：
1. **立即停止**當前操作
2. **承認錯誤**：明確說明哪裡做錯了
3. **重新承諾**：說明將如何改進
4. **徵求確認**：詢問用戶是否接受當前做法

---

## 四、適用範圍

本規則適用於：
- 所有程式碼修改任務
- 所有 Git 操作
- 所有多步驟工作流
- 任何需要連續工具呼叫的場景

🔑 addPart() 去重合併規則
  1. 以 partNo 為主鍵，partsMap.get(partNo) 查詢是否已存在
  2. 首次出現：直接寫入完整記錄，id = partNo
  3. 重複出現：只補充空白欄位（已有值的欄位不覆蓋）
  4. alternates[]：多次出現的別稱陣列以 Set union 合併去重
  5. 別稱品質過濾 (sanitizeAlternates)：僅接受 /^[A-Z0-9][A-Z0-9-]*$/i 品號格式，排除備註/說明文字（如「Ecomed專用，黏管尺寸客製化」）被誤錄為別稱
  6. 最終輸出 693 筆去重品號 + 181 組 BOM 組立關係（種子轉譯不變量，由 verifyCoreLogic.js 守護；組件圖掃描可再增量）

    "parents":  { "C01-001": ["SA001", "SB003"]    }   // childId → 所屬組件清單

3 PartItem 型別定義與欄位說明

定義於 src/types.ts，每個品號在記憶體中的完整資料結構：

欄位型別屬性說明來源
idstring必填記錄唯一識別符。Master JSON 中等於 partNo；手動新增為 custom-{timestamp}buildMaster / 手動新增
partNostring必填廠內或客戶品號，搜尋與 BOM join 的主要 key種子 JSON
namestring必填品號中英文名稱，fallback 為 partNo種子 JSON
customerstring必填客戶名稱（廠內品號通常為空字串），用於篩選與分類種子 JSON
categorystring?選填品號分類描述，如 單品零件、SA組立buildMaster
colorstring?選填零件顏色，來自 internalParts 顏色 欄位internalParts
materialstring?選填原料材質，來自 internalParts 原料 欄位internalParts
notesstring?選填備註欄位，手動填寫手動
alternatesstring[]?選填別稱品號清單（廠客對照、替代料號）；圖檔比對與搜尋遍歷全部別稱customerPartNumbers 雙向綁定
itemType'part' | 'assembly'衍生欄位由 isAssemblyPartNo() 即時推導，不寫入儲存enrichParts()
componentsstring[]?衍生欄位組件的子件品號清單，從 bom.children[partNo] 即時查詢，不寫入儲存enrichParts()
usedInAssembliesstring[]?衍生欄位零件被哪些組件使用，從 bom.parents[partNo] 即時查詢，不寫入儲存enrichParts()
衍生欄位保護：stripDerivedFields() 在落檔前移除 itemType / components / usedInAssemblies，確保儲存格式僅含主檔欄位。BOM 關係每次從記憶體 childrenMap/parentsMap 即時重算。

4 資料載入路徑 (Runtime Loading)

執行環境品號載入BOM 載入持久化
本地模式 (Express)GET /api/parts → master.json .partsGET /api/bom → master.json .bomlocalStorage + PUT /api/parts debounce 800ms
GitHub Pages 靜態模式API 攔截返回 []，需手動匯入攔截返回 {children:{}, parents:{}}sessionStorage，不持久化
🔄 App.tsx 啟動流程
  1. useState 初始化：非靜態模式從 localStorage 讀入上次資料並執行 enrichParts()
  2. useEffect：並行呼叫 initBOM()（載入 BOM 映射表）與 loadParts()（載入品號清單）
  3. loadParts() 回傳後呼叫 enrichParts()，所有衍生欄位即時計算
  4. 若品號列表為空，自動打開 ExportImportModal
  5. 圖檔資料夾：restoreImageFolder() 嘗試恢復 OPFS 資料夾句柄
  6. OCR 快取：loadOcrCache() 從 IndexedDB 載入上次掃描結果

5 BOM 衍生欄位計算 (enrichParts)

BOM 引擎定義於 src/utils/bomEngine.ts，在記憶體維護三份資料結構：

記憶體變數型別內容
childrenMapRecord<string,string[]>組件 partNo → 子件 partNo[]（181 組）
parentsMapRecord<string,string[]>子件 partNo → 所屬組件 partNo[]（反向索引）
assemblySetSet<string>childrenMap 所有 key 的集合（快速組件判斷）
⚙️ isAssemblyPartNo() 判斷順序
  1. partNo 在 assemblySet 中存在 → assembly
  2. partNo 大寫後以 MDXE 開頭 → assembly（前綴規則）
  3. 否則 → part

遞迴 BOM 查詢（最大深度 5）

getComponentsForAssembly() 展開組件所有子件（含子組件遞迴）；getAssembliesForPart() 反向查詢零件被哪些組件使用。兩者均以 visited Set 防止循環引用。

品號改名連鎖更新 (renamePartNo)

品號改名時自動遍歷 childrenMap 所有 key 與 value 替換，並重建 parentsMap 與 assemblySet，保持 BOM 關係完整性。

6 圖檔解析邏輯 (Image Resolution)

定義於 src/utils/imageResolver.ts，resolveAllImages() 依以下三策略依序嘗試：

優先順序策略機制via
1檔名比對imageLib.matchAll(partNo, alternates)：比對資料夾中所有檔名是否包含品號或別稱（大小寫正規化）file
2手動綁定查詢 localStorage['pn_lookup_image_bindings']：以 partNo 及所有別稱為 key 尋找綁定檔名binding
3OCR 辨識正規化比對 ocrIndex（IndexedDB）中每個圖檔的 OCR 文字是否包含品號字串ocr
別稱展開搜尋：以 [partNo, ...alternates] 作為搜尋鍵集合同步比對，任一別稱命中即成功，解決廠內與客戶品號命名差異導致圖檔找不到的問題。

7 心智圖分類引擎 (MindMap Classifier)

定義於 src/utils/mindmapClassifier.ts，classifyPart(item) 依以下優先順序分類：

🧠 classifyPart() 分類優先順序
  1. 精確品號比對 (exact)：ICU 插袋針 / 採藥針 8 個子類的預定義 Set（來自產品識別教育訓練 PDF）
  2. 廠內品號前綴比對 (pattern)：取 partNo 前 3 字元比對 FACTORY_PREFIX_MAP 10 個規則組（A01~H00 廠內零件 + K/Q 連接管）
  3. 組件判斷 (inferred)：isAssemblyPartNo() → SA/SB/SC/SD/特殊/MDXE/MDXI Set 組件
  4. 客戶欄位比對 (customer_field)：customer 字串含 BD / MPS / Biometrix / Vivus
  5. Fallback：unclassified — 待人工分類

心智圖節點深度與卡片尺寸對應

深度 (Depth)代表節點卡片寬度說明
0 — Root凱益 — 產品識別導圖288px根節點
1廠內品號 / 客戶品號 / 待人工分類240px主分類
2零件 / 組件 / Set / ICU / BD / MPS / Biometrix / Vivus204px次分類
3 (葉類別)T接頭 / Y管 / SA / 插袋針 等320px含品號列表展開
4 (ICU 子類)透氣口 / Clave / 不透氣 / 奶嘴 / 9035 / 花系列168pxMini 品號卡片
Layout 技術細節：使用 react-d3-tree，horizontal 模式下 nodeSize.x=390 控制水平欄距（≥ 320px 卡片），nodeSize.y 動態切換（收合 65px / 展開 155px，依展開節點數）。D3 原生 pan/zoom (scaleExtent: 0.2~3)。

10 別稱去重規則 (Alternates Dedup)

定義於 src/utils/alternates.ts，dedupeAlternates(list, selfPartNo)：

🧹 去重規則
  • 全部轉大寫進行唯一性比對（Set<string>），保留原始大小寫輸出
  • 過濾空字串與空白項目
  • 過濾與 selfPartNo 相同的項目（品號不應出現在自己的別稱中）
  • 若去重後長度為 0，回傳 undefined（不寫入空陣列，節省儲存空間）
觸發時機：① 使用者在 AdminPanel 新增/修訂品號儲存時；② buildMaster.js addPart() 合併 alternates 時（Set union）

12 組件圖掃描增補 (Assembly Image Scan)

定義於 scripts/scanAssemblyImages.js。Excel 原始資料可能並非全部品項，且組件圖頁面內通常會列出組成該組件所需的全部零件（PART NO. / DESCRIPTION / MATERIAL）。本腳本從組件圖頁面文字中提取零件清單，補足 Excel 之外的品項與 BOM 關係。

🔍 掃描範圍
  • rawdata/圖檔/客戶圖面/Sub-Assembly — 客戶組件圖（如 BD-8003875、SC0044）
  • rawdata/圖檔/產品資料/廠內組件圖面（SB、SC 系列）
  • rawdata/圖檔/產品資料/綜合圖面
⚙️ 掃描流程
  1. PDF 文字層提取：使用 pdfjs-dist/legacy 讀取前 6 頁的 getTextContent()
  2. 品號 token 擷取：正規化後以 /^[A-Z]{0,4}\d{1,4}(?:-[A-Z0-9]+)+$/i 過濾，排除日期（2023-05-15）、ISO 標準尾號（8536-4）
  3. 比對 master：以 partNo + alternates 的正規化索引命中「已知零件」，未命中且長度 ≥ 5 者列為「候補品號」
  4. 組件對應：檔名去除 (Rev.X) 與 _Rev.X 尾綴即組件品號；-C 客戶版本尾綴自動合併至標準品號（如 SB0083-C → SB0083）
  5. 產出：報告寫入 data/assembly-scan-report.json 供人工確認
📝 套用參數
  • --apply：將已比對成功的「組件 → 已知零件」BOM 關係寫入 master（例：R1-2392 組件圖 → R1-3373、R1-3509、R1-2391）
  • --auto：額外將「組件圖檔名對應、但 Excel 未收錄的組件」補建為新零件（category：組件圖候補），如 BD-8003875、SC0044
人工確認邊界：「候補品號」僅代表在組件圖頁面內文出現但 Excel/master 未收錄，可能是真品號也可能是材質/標準文字誤擷（如 LDPE PAXOTHENE NA207-66）。腳本僅輸出報告，不會自動把候補品號加入 master，一律需人工確認。
不變量守護：verifyCoreLogic.js 種子轉譯維持固定 693 筆；master 檔允許 ≥ 693（組件圖掃描 --apply 可增量，當前 693 筆基線）。

🧹 清洗作業重點（MECE 原則）
  • 剔除 100% 完全重複列；產品編號 / 組件編號 達 100% 唯一性
  • 清除不可見特殊字元（\xa0 不換行空格）、頭尾空格、字串內換行
  • 補齊缺失欄名（如第 9 欄補 備註、第 11 欄補 備註）
  • 跨表比對（對照表 vs 廠內品號）與異常列紀錄
最終統合：階段七將 7 張工作表全數合併為 master_table_unified.json（meta.totalSheets: 7），共 428+248+172 品號資料與 SA/SB/SC/SD 共 181 組 BOM。

合併規則（convertUnifiedSeedToMaster）

🔑 四大來源 → master 的映射
  1. 去重：以 partNo 為 key 存入 Map；後筆僅補齊缺漏欄位（customer/name/color/material/alternates），不覆蓋既有值
  2. 別稱淨化（sanitizeAlternates）：只收 /^[A-Z0-9][A-Z0-9-]*$/i 品號格式 + Set 去重，排除備註/說明文字誤錄
  3. internalParts：品號 = 產品編號；別稱 = 零件編號(客) + 產品編號(舊)
  4. customerParts：品號 = 產品編號（或 品號）
  5. customerPartNumbers（雙向建檔）：廠內品號的別稱含客戶料號與圖面編號；客戶料號本身也建為品項（別稱 = 廠內品號或圖面編號）。圖面編號進入別稱是圖檔檔名能命中品號的關鍵
  6. bomHierarchy：每個 assemblyId 建為組件品項（category = {level}組立）；children 逐一 addBomLink 並為子品號建檔
  7. 產出對稱索引：bom.children（組件 → 子件[]）+ bom.parents（子件 → 組件[]）
唯一真源原則：data/pn-lookup-master.json（version: 3.1.0）為唯一真源；前端衍生欄位一律即時推導（見 §7），落檔前剝除。

4 組件圖掃描與 BOM 補強 (scanAssemblyImages.js)

組件圖（PDF）頁面內文常列出該組件所需全部零件（PART NO. / DESCRIPTION / MATERIAL），可補足 Excel 未涵蓋的 BOM 關聯。

圖檔檔名命名規則（實測統計，1514 檔）

命名規則：品號 + 版本 + 其他後綴，版本與後綴的連結方式不一 — 可能是 _ 底線、() 括號或 - 連字符。
樣式數量範例
(Rev.X) 括號版本 + -C933A01-200-111(Rev.A)-C.pdf
尾綴 _mdx20427-0246-MC_08_mdx.pdf
尾綴 _NN（版本數字）169R1-10002_01.pdf、R1-1000_8.pdf
尾綴 _XX（字母/其它）10127-0338_3_mdx.pdf
尾綴 -MC_xx6775-0485-MC_29.pdf
含 Rev23BD-8003875_Rev.04.pdf
無後綴16R1-15853.pdf
特殊（SPC 文件）1SPC0014799_10_R1-2361.pdf

檔名 → 組件品號（assemblyIdFromFileName）

✂️ 剝除順序
  1. 副檔名
  2. 括號內容 \([^)]*\)（(Rev.A) 等版本資訊）
  3. 尾綴 Rev.XX / RevXX
  4. 尾綴 -C（客戶版本）

組件 ID 標準化（resolveAssemblyId，v7.8.5）

🔗 四層解析（檔名衍生 ID → master 標準品號）
  1. 精確命中：norm(id) 在 master 索引中 → 直接回傳標準品號
  2. 逐層剝除後綴：每剝一層即查 master（支援多層組合，如 R1-15853_03_mdx）：
    ① _mdx　② -MC_xx　③ -C　④ _NN　⑤ Rev
  3. 最乾淨形式：全部剝除後仍未命中 → 回傳最剝除的形式（合併同家族版本，例：R1-10278-MC_04_mdx 與 R1-10278-MC_04 合併為 R1-10278）
  4. 內文自身品號：圖面內文已知候選為組件 ID 正規化前綴、且後續首字元非數字（邊界防誤判，例：R1-15853 是 R1-15853_03_mdx 的前綴 → 解析為自身）
自身版本圖跳過：解析後 p.partNo === assemblyId（如 R1-15853_03 → R1-15853）即為該品號自己的版本圖面，不寫入 BOM（避免偽自連）。
噪音過濾：組件 ID 含中文/空白等非 /^[A-Z0-9][A-Z0-9_.\-]*$/i 字元者（如 PN-0002_D10-210-251-1 包裝說明書）不作為 BOM 父鍵。

PDF 內文 → 零件候選（extractPartNoCandidates）

🔍 擷取規則
  • Token 正規式：/^[A-Z]{0,4}\d{1,4}(?:-[A-Z0-9]+)+$/i（1~4 字母 + 數字 + 破折號）
  • 排除：日期 YYYY-MM-DD、ISO/IEC/EN 標準尾號、純 \d{3,5}-\d{1,2}
  • 每張圖取前 6 頁文字；norm() 正規化（去除全部非 A-Z0-9 + 轉大寫）
  • master 索引：Map<norm(品號或別稱) → 標準品號>；命中 → known[]，未命中且長度 ≥ 5 → unknown[]（候補）
  • 報告輸出：data/assembly-scan-report.json

寫入 BOM 旗標

旗標行為
--apply已知零件寫入 bom.children[組件ID]（去重），並重建 bom.parents
--auto--apply + 將未登錄組件 ID 自動收錄為新零件（category 組件圖候補）
--parent-of <PN>反向識別：列出內文包含該品號的所有組件圖（可搭 --apply 寫入）

5 前端圖檔檔名比對規則 (imageLibrary.ts)

🧮 正規化與邊界（normalize / isMatchedSegment）
  1. normalize(s)：去除所有非 A-Z0-9 字元 + 轉大寫（符號一律忽略）
  2. isMatchedSegment(sNorm, pnNorm)：相等 → 命中；sNorm 以 pnNorm 開頭且後續首字元不是數字 → 命中
    ✅ V1、RevA 允許　❌ B0030、B0031 拒絕（防止 B-003 誤吞 B-0030~B-0039）
📂 檔名 → 品號 前向比對（findForCandidate / findAllForCandidate）
  1. 先比對整個檔名（去副檔名、去符號）
  2. 再以分隔符 _、空白、()、[]、,、/ 拆成片段逐一比對（任一片段等於品號或符合邊界規則即命中）
    例：R1-15853_03_mdx.pdf → 片段 R1-15853、03、mdx → 命中 R1-15853
多別稱比對：matchFile / matchAllFiles 依 [品號, ...別稱] 逐一比對；matchAll 收集所有命中檔名並以檔名去重。

6 圖檔解析優先序與反向識別 (imageResolver.ts)

resolveAllImages() 依以下四策略依序嘗試：

優先順序策略機制via
1檔名比對matchAll(品號 + 別稱)：整檔名 → 片段逐一比對（§5 規則）file
2手動綁定localStorage['pn_lookup_image_bindings']：品號及所有別稱 → 檔名binding
3OCR 內文圖檔 OCR 文字（normalize 後）包含品號/別稱正規化字串ocr
4本體推理僅當 ①②③ 皆無結果：取「父組件圖面」（relatedParts = usedInAssemblies）作為推理來源inference
OCR 快取：IndexedDB 鍵 = 檔案名稱（ocrKeyForFile）；舊複合鍵 名稱|size|lastModified 由 normalizeCacheKey 向後相容。

反向識別：此品號可組成哪些產品（findParentProducts，v7.8.4）

🔁 三步驟（與前向比對互逆）
  1. 掃描所有已辨識圖檔內文，找出包含目標品號（品號 + 別稱）的圖檔
  2. 依檔名反查圖檔所屬品號：片段等於品號，或片段以品號開頭且後續首字元非數字；先查手動綁定反向索引
  3. 彙整候選產品並排除自身（owner === partNo）；僅供人工「加入 BOM 關聯」確認，不自動寫入

7 BOM 引擎 (bomEngine.ts)

記憶體變數型別內容
childrenMapRecord<string,string[]>組件 partNo → 子件 partNo[]（249 組）
parentsMapRecord<string,string[]>子件 partNo → 所屬組件 partNo[]（computeParentsMap 對稱推導）
assemblySetSet<string>childrenMap 所有 key 的集合
⚙️ 組件判定（isAssemblyPartNo）
  1. partNo 在 assemblySet 中（BOM 階層註冊過）→ 組件
  2. partNo 大寫後以 MDXE 開頭（前綴規則）→ 組件
  3. 否則 → 零件
🔗 唯一真源推導（enrichParts）與關係展開
  • enrichParts：itemType / components / usedInAssemblies 一律由 BOM 地圖即時產生（鍵比對支援大小寫）；落檔前 stripDerivedFields 移除
  • getComponentsForAssembly：自訂物料單（components 欄位）→ BOM 子零件遞迴（深度 ≤ 5，visited 防環）
  • getAssembliesForPart：usedInAssemblies 顯式目標 → 父組件遞迴
未登錄組件顯示（v7.8.5）：父組件 ID 無法對應 master 品號時，仍以 unregistered: true 的佔位列回傳（「未登錄」灰階、不可點擊），「本零件可組成的組件」欄位不無聲空白。
